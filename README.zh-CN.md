# mac-screenshots-to-photos

**iPhone 截图自动进相册，凭什么 Mac 截图不行？**

在 iPhone 上，每张截图都进照片图库——可搜索、自动同步、有云备份。
在 Mac 上，同一个动作却只是往桌面上丢一个 PNG 就不管了。
这个小项目用**纯 macOS 原生零件**补上这个缺口——不装第三方软件、
没有常驻进程、没有需要维护更新的东西。

[English README](README.md)

## 效果

```
Cmd+Shift+3/4          （你截一张图）
   │
   ▼
监视文件夹              （macOS 把截图存到这里——系统自带设置）
   │
   ▼
文件夹动作              （macOS 发现新文件——系统自带监听）
   │
   ▼
14 行 AppleScript      （叫照片 App 导入；只有导入成功才删源文件）
   │
   ▼
照片 App ──► iCloud ──► 你的 iPhone / iPad / 其他 Mac
```

- 截图几秒内出现在照片 App，随后同步到所有设备。
- 照片会对截图做 OCR——**可以按截图里的文字搜索**。
- 源文件自动删除，桌面上不再堆积截图坟场。
- 结构性安全：导入失败时源文件原地保留，绝不会删掉没安全入库的东西。

## 安装

```bash
git clone https://github.com/gnehiur/mac-screenshots-to-photos.git
cd mac-screenshots-to-photos
./install.sh
```

**运行前**，先打开 **照片 → 设置… → 通用**，勾上
**"导入：将项目拷贝到照片图库"**。安装脚本会要求你确认这一点，
不确认就拒绝安装——原因见下面的《死链陷阱》。

首次运行 macOS 会弹几次授权（控制"系统事件"；第一张截图导入时会再
问一次控制"照片"）。每个只问一次，点允许即可。

自定义监视文件夹：`./install.sh "$HOME/别的路径"`。

完全卸载：`./uninstall.sh`（截图恢复存桌面，图库内容不受影响）。

## 死链陷阱（值得读一遍）

照片 App 有两种导入方式：

- **拷贝式**（勾上）：照片保存自己的副本。原文件从此可以随便删，
  照片正常上传 iCloud。
- **引用式**（不勾）：照片只存一张"便条"——"文件在某某路径"。
  引用式的照片**永远不上 iCloud**；原文件一旦被挪动或删除，
  这张照片就变成只剩缩略图的死链。

本管线会在导入后删除源文件。如果配上引用式，每张截图都会在入库
瞬间变成孤儿——所以拷贝式是硬性前提，安装时强制确认。
（这份 README 之所以存在，是因为作者用 1,242 条死链换来了这个教训。）

## 设计说明

每一环都是 macOS 原装机制，只是把它们接在了一起：

| 环节 | 机制 | 位置 |
|---|---|---|
| 截图落点 | `defaults write com.apple.screencapture location` | 系统偏好 |
| 文件监听 | 文件夹动作（Folder Actions） | 系统事件，自带 |
| 导入 | 照片 App 的 AppleScript 接口 | `import ... skip check duplicates` |
| 同步 / OCR / 搜索 | iCloud 照片 + 实况文本 | 照片 App 自带 |

为什么不用 Automator 自带的"将文件导入到照片"动作？因为它是黑盒：
哪天坏了（真的会悄悄坏），它只会说一句 "script failed"，别的什么都
不告诉你。14 行明文 AppleScript 干同样的活，坏了会大声报错，
而且读一遍就能修。

删除语句写在 `try` 块内、导入语句**之后**——导入不成功就执行不到
删除那一行。整个安全性就建立在这一个顺序决定上。

## 常见问题

**吃 iCloud 空间吗？** 吃，跟 iPhone 截图一样——重度截图党一年
大概几个 GB。它们是正经图库成员，以后想清理就是正常删照片。

**截图会混进主时间线吗？** 照片 App 的"媒体类型 → 截屏"会自动
归类，也可以用智能相册过滤。

**照片 App 正忙或磁盘满了的时候截图会怎样？** 导入失败，删除就
不会执行——文件在监视文件夹里等着。把它移出再移回即可重新触发，
或者直接手动导入。

**老版本 macOS 能用吗？** 在 macOS 26 上测试通过。只要系统带
文件夹动作和照片 App 的 AppleScript 接口就应该能跑。
