# mac-screenshots-to-photos

**iPhone 截图自动进相册，凭什么 Mac 截图不行？**

在 iPhone 上，每张截图都进照片图库——可搜索、自动同步、有云备份。
在 Mac 上，同一个动作却只是往桌面上丢一个 PNG 就不管了。
这个小项目补上这个缺口，有两种模式：

- **经典模式**——**纯 macOS 原生零件**：不装第三方软件、没有常驻进程、
  没有需要维护更新的东西。截图几秒内进照片。
- **快速模式**——一个很小的常驻助手（约 200 行 Swift，零依赖），另外把
  每张截图**在截完约 0.1 秒内放进剪贴板**，切到聊天窗口直接 ⌘V 就能发。
  见下面的[《快速模式》](#快速模式截图约-01-秒进剪贴板)。

[English README](README.md)

## 效果

```
Cmd+Shift+3/4          （你截一张图）
   │
   ▼
监视文件夹              （macOS 把截图存到这里——系统自带设置）
   │
   ▼
文件夹动作              （macOS 发现新文件——系统自带监听）
   │
   ▼
14 行 AppleScript      （叫照片 App 导入；只有导入成功才删源文件）
   │
   ▼
照片 App ──► iCloud ──► 你的 iPhone / iPad / 其他 Mac
```

- 截图几秒内出现在照片 App，随后同步到所有设备。
- 照片会对截图做 OCR——**可以按截图里的文字搜索**。
- 源文件自动删除，桌面上不再堆积截图坟场。
- 结构性安全：导入失败时源文件原地保留，绝不会删掉没安全入库的东西。

## 安装（经典模式）

```bash
git clone https://github.com/gnehiur/mac-screenshots-to-photos.git
cd mac-screenshots-to-photos
./install.sh
```

**运行前**，先打开 **照片 → 设置… → 通用**，勾上
**"导入：将项目拷贝到照片图库"**。安装脚本会要求你确认这一点，
不确认就拒绝安装——原因见下面的《死链陷阱》。

首次运行 macOS 会弹几次授权（控制"系统事件"；第一张截图导入时会再
问一次控制"照片"）。每个只问一次，点允许即可。

自定义监视文件夹：`./install.sh "$HOME/别的路径"`。

完全卸载：`./uninstall.sh`（截图恢复存桌面，图库内容不受影响）。

## 快速模式：截图约 0.1 秒进剪贴板

大多数截图都是为了马上贴出去。经典模式下你还得去拖文件；快速模式让截图在你
切到聊天窗口之前就**已经在剪贴板里了**，同时照样存进照片。

```
Cmd+Shift+3/4（或程序坞里的「截屏」App）
   │
   ▼
监视文件夹              （文件立刻落盘——浮动缩略图已关）
   │  FSEvents，毫秒级
   ▼
screenshot-sync         （常驻 LaunchAgent，fast/main.swift）
   ├─► 剪贴板           （PNG 图片数据，截完约 0.1 秒）  ──►  ⌘V
   └─► 照片             （PhotoKit 拷贝入库；只有导入成功才删源文件）
```

```bash
cd mac-screenshots-to-photos/fast
./install.sh                     # 或 ./install.sh "$HOME/别的路径"
```

需要 `swiftc`（Xcode 命令行工具：`xcode-select --install`）。安装脚本会编译
助手、装到 `~/Applications/screenshot-sync.app`、以 LaunchAgent
`com.gnehiur.screenshot-sync` 常驻、关掉浮动缩略图，并停用同一文件夹上的
经典文件夹动作，免得重复导入。macOS 会问一次是否允许它**添加到照片**——点允许。
日志：`~/Library/Logs/screenshot-sync.log`。卸载：`fast/uninstall.sh`。

**两台 Mac 并排用（通用控制）？** 截图快门声在每台 Mac 上都是同一个文件
（`/System/Library/Components/CoreAudio.component/Contents/SharedSupport/SystemSounds/system/Screen Capture.aif`），
放在只读的系统卷上，听不出是哪台截的。给其中一台加一声额外提示音，紧跟在快门声后面：

```bash
./install.sh "$HOME/Pictures/Screenshots Auto-Import" /System/Library/Sounds/Bottle.aiff
```

听到两声就是这台，一声就是另一台。提示音在系统建临时文件时触发（快门响后约 10 毫秒），
再等 140 毫秒才放（第三个参数，单位毫秒），免得被快门的起音和扬声器唤醒吞掉开头。`tools/sound-picker/` 是一个本地试听小页面
（先 `python3 build.py`，再把这个文件夹用本地服务打开 `index.html`）。只有存进文件夹
的截图会触发提示音；`⌃⇧⌘3/4`（只进剪贴板）不写文件，不会响。

**经典模式为什么慢。** 文件夹动作不是即时的：macOS 会攒一批文件夹变化，
1～5 秒后才触发，然后还要启动脚本（Automator 工作流再多一两秒）。另外，
右下角的浮动缩略图会让文件晚约 5 秒才真正写盘。快速模式把三处都去掉了：
零延迟的 FSEvents、早已在跑的进程、关掉缩略图。

**为什么放进剪贴板的是图片数据而不是文件。** 复制的「文件」其实只是一个路径：
源文件一删（本管线会删）就失效，到另一台 Mac 上更是毫无意义。助手直接写入
PNG 数据（`public.png`），所以文件删了照样能贴，任何接受图片的 App 都能贴；
带剪贴板同步的远程桌面（比如 UU 远程）也能把真正的图片带到另一台机器上。

**怎么判断文件写完了。** macOS 先写一个隐藏的 `.截屏…png` 临时文件，写完再改名。
助手忽略点开头的文件，并且检查 PNG 是否以 `IEND` 块结尾才使用，没写完就每
50 毫秒重试，最多等 5 秒。

**这里没有死链陷阱。** PhotoKit 不管「拷贝到图库」那个勾，一律拷贝入库。
删除照样只在导入成功之后执行；如果没给照片权限，截图仍会进剪贴板，文件留在
文件夹里。

**两台 Mac？** 每台各装一份。开着 iCloud 照片的话，任一台截的图都会出现在
两边图库里；本项目自己不做跨机器同步。

## 死链陷阱（值得读一遍）

照片 App 有两种导入方式：

- **拷贝式**（勾上）：照片保存自己的副本。原文件从此可以随便删，
  照片正常上传 iCloud。
- **引用式**（不勾）：照片只存一张"便条"——"文件在某某路径"。
  引用式的照片**永远不上 iCloud**；原文件一旦被挪动或删除，
  这张照片就变成只剩缩略图的死链。

本管线会在导入后删除源文件。如果配上引用式，每张截图都会在入库
瞬间变成孤儿——所以拷贝式是硬性前提，安装时强制确认。
（这份 README 之所以存在，是因为作者用 1,242 条死链换来了这个教训。）

## 设计说明

经典模式——每一环都是 macOS 原装机制，只是把它们接在了一起：

| 环节 | 机制 | 位置 |
|---|---|---|
| 截图落点 | `defaults write com.apple.screencapture location` | 系统偏好 |
| 文件监听 | 文件夹动作（Folder Actions） | 系统事件，自带 |
| 导入 | 照片 App 的 AppleScript 接口 | `import ... skip check duplicates` |
| 同步 / OCR / 搜索 | iCloud 照片 + 实况文本 | 照片 App 自带 |

快速模式换掉了中间几环：

| 环节 | 经典 | 快速 |
|---|---|---|
| 文件监听 | 文件夹动作（1～5 秒） | FSEvents，零延迟（毫秒） |
| 剪贴板 | — | `NSPasteboard`，PNG 数据 |
| 导入 | 照片 AppleScript | PhotoKit `PHAssetCreationRequest`（一律拷贝） |
| 权限 | 控制系统事件 + 照片 | 只要「添加到照片」 |
| 运行方式 | 触发时才跑 | LaunchAgent 常驻，约 10～35 MB 内存，平时空闲 |

为什么不用 Automator 自带的"将文件导入到照片"动作？因为它是黑盒：
哪天坏了（真的会悄悄坏），它只会说一句 "script failed"，别的什么都
不告诉你。14 行明文 AppleScript 干同样的活，坏了会大声报错，
而且读一遍就能修。

删除语句写在 `try` 块内、导入语句**之后**——导入不成功就执行不到
删除那一行。整个安全性就建立在这一个顺序决定上。

## 常见问题

**吃 iCloud 空间吗？** 吃，跟 iPhone 截图一样——重度截图党一年
大概几个 GB。它们是正经图库成员，以后想清理就是正常删照片。

**截图会混进主时间线吗？** 照片 App 的"媒体类型 → 截屏"会自动
归类，也可以用智能相册过滤。

**快速模式会处理文件夹里原有的截图吗？** 不会，只处理它启动之后新出现的文件。

**照片 App 正忙或磁盘满了的时候截图会怎样？** 导入失败，删除就
不会执行——文件在监视文件夹里等着。把它移出再移回即可重新触发，
或者直接手动导入。

**老版本 macOS 能用吗？** 在 macOS 26 上测试通过。只要系统带
文件夹动作和照片 App 的 AppleScript 接口就应该能跑。
